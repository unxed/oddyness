# Предмет исследования: что именно представляет собой платформа

Это **карта оригинального продукта и исследовательских задач**, а не проект
устройства oddyness. Уровень совместимости ещё предстоит согласовать.

## Ключевое различие

По [официальному обзору](https://1c-dn.com/1c_enterprise/platform_architecture_overview/)
приложение описывается метаданными: структурами данных, связями, поведением,
представлениями и ограничениями доступа. Платформа даёт механизмы исполнения.
Поэтому реализация языка плюс формы сама по себе ещё не воссоздаёт платформу.
Прикладная бухгалтерия, зарплата и бизнес-процессы конкретной организации —
отдельные решения поверх неё.

В scope **механизмы** справочника/документа/регистра/формы; вне scope —
предметные справочники, проводки, законодательство и отчёты конкретной
конфигурации. Искусственные метаданные в тесте нужны только как вход платформы.

## Словарь

| Термин | Рабочее значение для исследования |
| --- | --- |
| Платформа | Среда разработки, исполнения и администрирования прикладных решений |
| Конфигурация | Описание прикладного решения: метаданные, модули, формы, макеты и другое |
| Информационная база | Данные и необходимые описания прикладного решения; не просто таблицы ERP |
| Конфигуратор / Designer | Средство изменения конфигурации и административных операций |
| EDT | Отдельная среда разработки и своё представление проекта |
| Встроенный язык / BSL | Язык модулей платформы; не язык запросов |
| SDBL | Принятое в инструментах экосистемы название языка запросов 1С |
| Проведение | Механизм отражения документа в учёте; конкретные движения задаёт приложение |
| Регистр | Специализированное описание хранения/обработки записей; не просто UI-таблица |
| СКД / DCS | Система компоновки данных: схема, настройки, вычисления и вывод отчёта |
| Управляемая форма | Описание формы, данных, команд и обработчиков, отображаемое клиентом |
| Режим совместимости | Версионное поведение конфигурации; отличается от номера установленной платформы |

Термины сверяются с [руководствами](https://1c-dn.com/library/tutorials/) и
[официальным глоссарием](https://1c-dn.com/library/tutorials/practical_developer_guide_glossary/).

## Карта возможностей и точек проверки

Приоритет в таблице — **приоритет исследования**, не обещанный порядок разработки.
Списки механизмов не задают обязательное полное покрытие первого релиза.

| Область | Что инвентаризировать | Основное свидетельство | Приоритет и неизвестное |
| --- | --- | --- | --- |
| Язык | RU/EN-ключевые слова, регистр, области, процедуры, функции, параметры, исключения, директивы, асинхронность | Официальная справка + парсеры + минимальные программы | Высокий: контексты компиляции и исполнения |
| Значения | Число, дата, строка, булево, Null, Неопределено; преобразования и сравнения | [Type System](https://1c-dn.com/1c_enterprise/type_system/) + опыты | Высокий: точность, округление, пустые значения |
| Контексты | Модули объекта, менеджера, формы, сеанса, общие; клиент/сервер | Руководство и выгрузки | Высокий: доступность API и жизненный цикл |
| Метаданные | UUID, типы реквизитов, ссылки, перечисления, справочники, документы, регистры | XML/EDT + mdclasses | Высокий: минимум необходимых прототипов |
| Объектная работа | Получение по ссылке, запись, удаление, события, табличные части | Искусственная конфигурация | Высокий: ссылка, объект и выборка — разные сущности |
| Запросы | Источники, параметры, соединения, группировки, итоги, временные и виртуальные таблицы | [Query language](https://1c-dn.com/library/query_language/) + грамматики SDBL | Высокий: не подмена SQL |
| Регистры | Сведения, накопление, бухгалтерия, расчёт; периоды, измерения, ресурсы, регистратор | Официальные учебные главы и тесты | Высокий: механизмы разной сложности |
| Транзакции | Запись/проведение, отказ, откат, параллельная работа, блокировки | [Учебный сценарий](https://1c-dn.com/library/tutorials/practical_developer_guide_locking_data_that_is_read_and_modified_during_posting/) + два сеанса | Высокий: нельзя подтвердить только одиночным запуском |
| Формы | Данные, команды, размещение, события, списки, выбор ссылок, пользовательские настройки | [Form data types](https://1c-dn.com/library/tutorials/practical_developer_guide_form_data_types/) + маленькие формы | Высокий: нужна наблюдаемая семантика событий |
| Разработка | Дерево метаданных, свойства, редакторы, диагностика, запуск и отладка | EDT/Designer docs, goWidgets | Высокий: что необходимо для первой законченной демонстрации |
| Отчёты | СКД, выражения, группировки, табличный документ, печать и макеты | Отдельные схемы и печатные образцы | Средний: XLSX-библиотека не реализует СКД |
| Безопасность | Пользователи, роли, права, RLS, привилегии, безопасный режим | Руководства + негативные тесты | Высокий при любом многопользовательском режиме |
| Обмен | JSON/XML/XDTO, HTTP/SOAP/OData, планы обмена, внешние компоненты | Публичные API/SDK и независимые клиенты | Средний: определить требуемую поверхность |
| Эксплуатация | Файловый/серверный режим, сеансы, задания, журналы, backup, миграции | Руководства администратора | Средний: границы первого окружения |
| Расширения | Заимствование объектов, обработчики, совместимость | Минимальное расширение и описание формата | Отдельное исследование; это платформенная возможность |
| Мобильность, кластер, облако | Мобильный рантайм, публикация, разделение данных, отказоустойчивость | Официальные обзоры и специальные стенды | Отложенное решение о scope |

## Пять независимых осей совместимости

1. **Языковая:** разбирается ли BSL и совпадают ли значения/исключения?
2. **Платформенная:** совпадают ли API, метаданные, записи, запросы и события?
3. **Форматная:** какие XML/EDT/контейнеры можно читать, писать, переносить?
4. **Поведенческая UI:** можно ли выполнить привычную работу, совпадает ли
   последовательность событий, клавиатурная навигация и выбор объектов?
5. **Интеграционная:** что видят внешние HTTP/OData/Native API/отладочные клиенты?

Есть ещё отдельные требования к скорости, переносимости и эксплуатации.
Успех на одной оси не означает успех на остальных. Запуск нескольких скриптов
не даёт права объявить «поддерживаются конфигурации 1С».

## Форматы, которые нельзя смешивать

| Вид | Что исследовать | Что из него не следует |
| --- | --- | --- |
| `.bsl`, `.os` | Текст модулей; `.os` обычно относится к OneScript | Одинаковый глобальный контекст и библиотеки |
| XML-выгрузка Designer | Configuration.xml, дерево объектов, модули и отдельные файлы свойств | Совпадение с внутренним хранением или EDT |
| Проект EDT | `.mdo`, модули и связанные ресурсы | Прямая загрузка в наш рантайм без преобразования |
| `.cf`, `.cfe` | Контейнер конфигурации/расширения | Что распаковка контейнера равна исполнению |
| `.epf`, `.erf` | Внешняя обработка/отчёт | Независимость от требуемой конфигурации |
| `.dt` | Выгрузка информационной базы | Что её можно трактовать как XML конфигурации |
| `.1CD` | Файловая база оригинальной платформы | Необходимость своего совместимого файлового DBMS |
| `.hbk` | Контейнер справки | Открытая лицензия содержимого |
| `.mxl` / табличный документ | Модель форматированного табличного вывода и её сохранение | Эквивалентность XLSX или обычному grid |

Опоры: руководство, раздел 2.17; [mdclasses](https://github.com/1c-syntax/mdclasses),
[v8unpack](https://github.com/saby-integration/v8unpack),
[tool1cd](https://github.com/e8tools/tool1cd),
[bsl-context](https://github.com/1c-syntax/bsl-context).
Поддержка импорта существующих конфигураций пока **не принята как обязательство**.

## Технические факты, способные изменить будущие решения

- Значения формы и прикладной объект — разные уровни. Для тонкого/веб-клиента
  официально описаны специальные структуры данных формы; перенос прямой
  ссылки на Go-объект в виджет не подтверждает соответствие этой модели.
- Язык запросов имеет виртуальные таблицы, разыменование ссылок и итоги.
  SQL-парсер или ORM не заменяют эти механизмы; стандартный SQL-backend может
  быть лишь строительным блоком.
- В рассмотренном Go-парсере числовой литерал уже превращён в `float64`.
  Потеря цифр на разборе необратима для последующего decimal-исполнения.
- Официальная глава 4.3.8 описывает десятичное число и предел **32 разряда**;
  это нужно подтвердить опытом на выбранной сборке. Не подставлять популярное
  предположение «38 цифр», размер NUMERIC в СУБД или 19 цифр библиотеки без проверки.
- В [исторической статье 1С](https://habr.com/ru/companies/1c/articles/269611/)
  файловый движок, язык и метаданные — отдельные компоненты. Это объяснение
  масштаба задач, не требование повторять C++-компоненты или файловый формат.

Ни один из этих пунктов не выбирает архитектуру oddyness. Они задают проверки,
которые должны предшествовать выбору.
