# Переиспользование: компоненты, инструменты и корпуса

## Как оценивались кандидаты

«Писать с нуля» здесь означает собственную реализацию платформенных механизмов,
а не переписывание XML, decimal, SQL-драйверов и парсеров. Готовая ERP или чужая
метаданная платформа не выбирается основой. Отдельные библиотеки, генераторы и
внешние инструменты могут сократить код.

Обозначения глубины: **C** — просмотрены отдельные исходники; **D** — README и
лицензия/метаданные; **L** — найдено направление, подробная проверка впереди.
Даже C не означает аудит всего проекта или запуск тестов. Ревизии и конкретные
пути сведены в [repositories.json](repositories.json). В колонке лицензий
указан обнаруженный текст верхнего уровня; зависимости и данные проверяются
отдельно перед реальным включением. Наш BSD-3-Clause не перелицензирует чужой код.

### Go-парсер: конкретные находки

На ревизии из реестра просмотрены `ast/tokens.go`, `ast/grammar.y`,
`ast/ast.go`, тесты и `go.mod`.

- `ast/tokens.go` преобразует число через `strconv.ParseFloat(..., 64)`.
  Последующее decimal-исполнение не вернёт потерянные исходные цифры. Для
  кандидата нужно проверить возможность сохранять текст числового литерала.
- `skipRegions()` пропускает строку с `#`; рядом авторский TODO об условиях
  препроцессора. Для анализа исходника это может быть допустимым компромиссом,
  для компиляции разных клиентских/серверных веток — отдельная задача.
- AST и pretty printer есть, но успешный разбор не определяет правила
  преобразований типов, передачу параметров, события объектов или запросы.
- `go.mod` содержит и косвенные зависимости, связанные с SQL-парсером.
  Нужен последующий разбор реально достижимого production-графа: длинный
  `require` сам по себе не означает включение всех пакетов в бинарник.
- Компиляция, полнота синтаксиса, асинхронные конструкции и аллокации не проверены
  запуском. До выбора нужен общий корпус с ошибочными и валидными программами.

**Вывод:** перспективный путь сокращения фронтенда, но не «язык уже готов».

### Гонец: что действительно релевантно

Просмотрены README, `go.mod`, LICENSE, часть `core/` и дерево реализации VM.
Язык позиционируется как 1С-подобный для микросервисов; у него собственные типы
и библиотеки. В `core/coreint.go` есть отдельное целое, в `core/coredecnum.go` —
decimal на зависимости `covrom/decnum`, в `core/coreifaces.go` — интерфейсы значений.
Это полезнее для нашего исследования, чем только сравнение синтаксиса.

README заявляет повторное использование памяти через пул и высокую скорость.
Эти заявления **не воспроизведены**: старый график пустого цикла не позволяет
предсказать скорость современных платформенных операций. Пул также не
гарантирует нулевых аллокаций на каждом пути.

**Вывод:** исследовать небольшие независимо применимые части и тесты; не
принимать диалект за спецификацию 1С и не переносить всю платформу микросервисов.

### 1cai-public: сверка с текущим содержимым

На проверенной ревизии README описывает **«Рентген»**, ранний доступ к локальному
ядру работы со снимками конфигурации, сравнением и проверками. Полное замещение
Designer/EDT заявлено как дальнейшее направление, а не установленный факт.

Проверены `go/go.mod`, `go/internal/scanner/scanner.go`, `strict.go`,
`go/internal/extractor/extractor.go`, `callgraph.go`:

- есть Go-сканер модулей и извлечение признаков/графа вызовов;
- обычный обход пропускает некоторые ошибки, strict-режим имеет отдельные
  проверки файлов, UTF-8 и SHA-256 — полезно для построения корпуса;
- extractor использует регулярные выражения и дополнительную обработку;
  это не основание считать его исполняющим парсером BSL;
- `internal/` и имя локального Go-модуля потребуют выделения пакета либо
  собственного адаптера: это не готовый публичный API для импорта в oddyness;
- Python/Rust/редакторские интеграции и инфраструктура AI не дают автоматически
  пользы ядру; можно изучать только нужные функции и тестовые сценарии.

**Вывод:** экономия в исследовательской оснастке и обработке исходников;
платформенный runtime, транзакции и формы этот проект за нас не реализует.

### OneScript и статья 2016 года

[Статья](https://habr.com/ru/articles/301064/) объясняет происхождение
независимого интерпретатора и реализации части стандартных классов.
[Сайт](https://oscript.io/) подтверждает возможность работы без библиотек 1С.
Современный README описывает .NET-поставки, включая Linux/macOS.
Это не меняет предпочтение инициатора писать oddyness на Go.

Можно использовать вне продукта как сравнительный рантайм для выделенного
подмножества языка и как источник собственных новых тестов. Результаты OneScript
помечать отдельно от результатов оригинальной 1С. Ошибки/расширения OneScript
не должны незаметно стать требованиями совместимости.

| Вариант | Подтверждённое назначение | Что проверить для oddyness |

| [ncruces/wasm2go](https://github.com/ncruces/wasm2go), MIT | Преобразует Wasm в Go; выход самодостаточен относительно стандартной библиотеки | Полнота Wasm для выбранного входа, размер/время сборки, host-вызовы и аллокации |
| Tree-sitter Wasm | Сборка грамматик BSL/SDBL в `.wasm` предусмотрена | Какой C/Wasm host ABI требует дерево разбора; наличие `.wasm` не означает готовую связку с wazero |
| Свой компилятор BSL → Wasm | Пока лишь возможное направление | Сначала семантика языка, decimal/строки/ссылки/исключения; готового квалифицированного компилятора в исследованном наборе нет |

У wasm2go README прямо предполагает доверенный вход; его нельзя автоматически
назначить песочницей для чужих конфигураций. Внешний host-вызов из любого
Wasm-runtime получает ровно те полномочия, которые ему дали. Wasm не реализует
права 1С, транзакции, глобальный контекст и формы.

Публичные пути `tetratelabs/wazero` и `wazero/wazero` на момент проверки разрешались
в один проект/HEAD; имя Go-модуля проверять по `go.mod`, а не менять вслед за URL.
Ни скорость, ни размер, ни пригодность для BSL не измерялись. Сравнивать нужно
одинаковую семантику и workload, а не пустой числовой цикл против базы данных.

## goWidgets: подтверждённая точка старта и недостающие контролы

На зафиксированном HEAD просмотрены README, `api.go`, `core/driver.go`, список
backend-тестов. Лицензия BSD-3-Clause. Проект заявляет native UI без CGO:
Win32, AppKit/Cocoa, GTK, Qt и headless. Поддержка на конкретных машинах здесь
не запускалась.

В `WidgetKind` есть Label, Button, CheckBox, TextView, Edit, ComboBox, ListBox,
ImageView, Canvas. Есть layout, диалоги, focus и tray menu. **TextView —
read-only**, а tray menu — не готовая система меню приложения. README отстаёт
от некоторых возможностей кода, поэтому инвентарь строился не только по нему.

| Потребность платформы | Состояние проверки | Что требуется исследовать/добавить в goWidgets |
| --- | --- | --- |
| Простая карточка | Базовые контролы есть | Валидация, обязательность, выбор типа и ссылок |
| Список объектов и табличная часть | ListBox есть, полноценный table/grid не найден в публичном наборе видов | Виртуализация, колонки, редакторы ячеек, сортировка, диапазон выбора |
| Дерево метаданных/иерархии | Tree-контрол в наборе видов не найден | Ленивая загрузка, клавиатура, свойства выбранного объекта |
| Редактор BSL | Read-only TextView и single-line Edit не заменяют редактор | Многострочное редактирование, подсветка, диагностика, позиции исходника |
| Рабочее место и команды | Окна и tray есть | Меню приложения, toolbar, вкладки, split panes, hotkeys |
| Табличный документ/печать | Canvas есть, готовой модели отчёта не найдено | Пагинация, шрифты, повторяемые заголовки, экспорт/печать |
| Масштаб и доступность | Есть DPI/focus-механизмы и backend-тесты | IME, screen reader, системные темы и большие наборы данных |

Это **инвентарь потенциальных работ**, не решение рисовать весь UI в Canvas.
Добавление нового контрола должно включать контракт, реализации нужных backend
и headless-проверки; конкретное решение обсуждается в проектировании.

## Аналоги, которые не выбираем фундаментом

[lsFusion](https://lsfusion.org/ru/alternativa-1c) полезен как сравнительный пример
метаданной бизнес-платформы, но его иной язык и устройство не подтверждают
совместимость с BSL. Odoo, ERPNext, Tryton и другие ERP могут подсказать
пользовательские сценарии, но не заменяют спецификацию платформы 1С и не
становятся основой oddyness по условию инициатора. Их исходники в этом шаге не
аудировались. 1С:Элемент/Executor также нужно отличать от языка/платформы 8.x;
родственный бренд не означает одинаковый контракт.

## Где экономия реальна, а где пока не найдена

Можно существенно сократить парсинг, форматные конвертеры, диагностическую
оснастку, SQL-доступ, общую сериализацию, decimal и native GUI.
В исследованном наборе не квалифицирован готовый Go-компонент, одновременно
реализующий метаданные 1С, платформенные значения и API, проведение/регистры,
SDBL с виртуальными таблицами, данные форм и СКД. Это **результат поиска**, а
не доказательство отсутствия такого проекта в мире.

Главный кандидат на собственный код — связывающая платформенная семантика.
Именно её объём нельзя оценивать количеством уже существующих лексеров.
