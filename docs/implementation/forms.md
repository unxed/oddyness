# Формы: состояние и команды без окна (P04)

Реализация — `internal/forms`. Форма справочника строится из метаданных и не знает о виджетах; окно goWidgets
(следующая часть P04) лишь отражает её состояние и пересылает команды. Правила проверки живут только здесь.

## Модель

- Контролы и порядок обхода: по полю метаданных — `edit` (строка, число, ссылка) или `checkbox` (булево), затем
  кнопки `save` и `close`. Идентификаторы стабильны и не зависят от подписей: `<справочник>/f/<поле>`,
  `<справочник>/b/save|close` (например `goods/f/goods-code`, `goods/b/save`).
- Команды: `SetText`, `SetChecked`, `Focus`, `FocusNext`, `FocusPrev`, `Save`, `Close`. Неизвестный контрол —
  `ErrUnknownControl`, неподходящая команда (текст в флажок) — `ErrWrongControl`, любая команда закрытой формы —
  `ErrClosed`; неудачная команда состояние не меняет.
- Проверка при `Save`: строки и числа обязательны (пустое или из пробелов — `required`), число — точный литерал
  (`value.Parse`), помещается в `digits`/`scale` поля (`Number.CheckPrecision`, лишние знаки отклоняются, а не
  округляются), ссылка — положительный номер записи или пусто. Ошибки хранятся по контролам, фокус уходит на
  первый неверный, `SaveFunc` не вызывается, результат — `ErrInvalid`; правка поля сбрасывает его ошибку.
- Без ошибок вызывается `SaveFunc(values)`: значения типизированы (`string`, `bool`, `value.Number`,
  `value.Ref` или `nil`). Её ошибка остаётся в `FormError`, форма открыта, ввод сохранён; успех закрывает форму
  (`Saved` возвращает значения).
- `Snapshot()` — стабильный текстовый снимок: заголовок формы, по строке на контрол (маркер фокуса `*`, вид,
  подпись, значение, ошибка), ошибка формы. Тесты сравнивают его с эталонами.

## Окно goWidgets (`internal/ui`)

`ui.Open(app, form, title, onDone)` строит окно goWidgets (пока — вертикальный стек, который даёт goWidgets):
подпись, `Edit` или `CheckBox` и строка ошибки на поле, кнопки «Сохранить» и «Закрыть», строка ошибки формы.
Ввод пользователя доходит до формы через `Edit.Text`/`CheckBox.Checked` (`OnChange`), клик — через
`Button.Clicked`; крестик окна закрывает форму; после успешного сохранения, «Закрыть» или крестика вызывается
`onDone` (по умолчанию `app.Quit`). Окно показывает ошибки формы и переводит фокус на первое неверное поле.
Общих контролов в oddyness нет — только те, что даёт goWidgets.

Зависимость: `github.com/unxed/goWidgets` (BSD-3-Clause) закреплена на ревизии `5f71d2bacbd1` (23-10-2026),
`github.com/ebitengine/purego` заменён на `github.com/unxed/pureffi` v0.1.19 — так же, как в `go.mod`
goWidgets (`replace` зависимости не наследуется); `github.com/unxed/kiwi-go` (BSD-3-Clause) приходит транзитивно.
Библиотеки goWidgets нет в Context7: API читался из `api.go`.

Проверка: `internal/ui` на headless-backend goWidgets (`goWidgets_BACKEND=headless`) без окна ОС: пустая форма и
«Сохранить» показывают ошибки обязательных полей; ввод сбрасывает ошибку поля; число с лишними знаками
отклоняется; исправление и «Сохранить» закрывают форму и завершают окно; правка закрытой формы ничего не меняет.
Ограничения: тест идёт в одной горутине (goWidgets закрепляет за ней поток интерфейса, у headless-backend
глобальное состояние), поэтому параллельные сценарии — отдельными процессами (следующая часть); ввод в тесте —
через свойства виджетов, а не через события ОС; нативные backend здесь не проверялись.

## Граница

Данные в памяти или в переданной `SaveFunc`; подключение к базе — P06. Реальный ввод в нативном окне и
параллельный прокликивающий harness по процессам и дисплеям — следующая часть P04; до неё ни один нативный backend
не объявлен проверенным.
