# Формы: состояние и команды без окна (P04)

Реализация — `internal/forms`. Форма справочника строится из метаданных и не знает о виджетах; окно goWidgets
(следующая часть P04) лишь отражает её состояние и пересылает команды. Правила проверки живут только здесь.

## Модель

- Контролы и порядок обхода: по полю метаданных — `edit` (строка, число, ссылка) или `checkbox` (булево), затем
  кнопки `save` и `close`. Идентификаторы стабильны и не зависят от подписей: `<справочник>/f/<поле>`,
  `<справочник>/b/save|close` (например `goods/f/goods-code`, `goods/b/save`).
- Команды: `SetText`, `SetChecked`, `Focus`, `FocusNext`, `FocusPrev`, `Save`, `Close`. Неизвестный контрол —
  `ErrUnknownControl`, неподходящая команда (текст в флажок) — `ErrWrongControl`, любая команда закрытой формы —
  `ErrClosed`; неудачная команда состояние не меняет.
- Проверка при `Save`: строки и числа обязательны (пустое или из пробелов — `required`), число — точный литерал
  (`value.Parse`), помещается в `digits`/`scale` поля (`Number.CheckPrecision`, лишние знаки отклоняются, а не
  округляются), ссылка — положительный номер записи или пусто. Ошибки хранятся по контролам, фокус уходит на
  первый неверный, `SaveFunc` не вызывается, результат — `ErrInvalid`; правка поля сбрасывает его ошибку.
- Без ошибок вызывается `SaveFunc(values)`: значения типизированы (`string`, `bool`, `value.Number`,
  `value.Ref` или `nil`). Её ошибка остаётся в `FormError`, форма открыта, ввод сохранён; успех закрывает форму
  (`Saved` возвращает значения).
- `Snapshot()` — стабильный текстовый снимок: заголовок формы, по строке на контрол (маркер фокуса `*`, вид,
  подпись, значение, ошибка), ошибка формы. Тесты сравнивают его с эталонами.

## Окно goWidgets (`internal/ui`)

`ui.Open(app, form, title, onDone)` строит окно goWidgets (пока — вертикальный стек, который даёт goWidgets):
подпись, `Edit` или `CheckBox` и строка ошибки на поле, кнопки «Сохранить» и «Закрыть», строка ошибки формы.
Ввод пользователя доходит до формы через `Edit.Text`/`CheckBox.Checked` (`OnChange`), клик — через
`Button.Clicked`; крестик окна закрывает форму; после успешного сохранения, «Закрыть» или крестика вызывается
`onDone` (по умолчанию `app.Quit`). Окно показывает ошибки формы и переводит фокус на первое неверное поле.
Общих контролов в oddyness нет — только те, что даёт goWidgets.

Зависимость: `github.com/unxed/goWidgets` (BSD-3-Clause) закреплена на ревизии `5f71d2bacbd1` (23-10-2026),
`github.com/ebitengine/purego` заменён на `github.com/unxed/pureffi` v0.1.19 — так же, как в `go.mod`
goWidgets (`replace` зависимости не наследуется); `github.com/unxed/kiwi-go` (BSD-3-Clause) приходит транзитивно.
Библиотеки goWidgets нет в Context7: API читался из `api.go`.

Проверка: `internal/ui` на headless-backend goWidgets (`goWidgets_BACKEND=headless`) без окна ОС: пустая форма и
«Сохранить» показывают ошибки обязательных полей; ввод сбрасывает ошибку поля; число с лишними знаками
отклоняется; исправление и «Сохранить» закрывают форму и завершают окно; правка закрытой формы ничего не меняет.
Ограничения: тест идёт в одной горутине (goWidgets закрепляет за ней поток интерфейса, у headless-backend
глобальное состояние), поэтому параллельные сценарии — отдельными процессами (следующая часть); ввод в тесте —
через свойства виджетов, а не через события ОС; нативные backend здесь не проверялись.

## Нативный backend: GTK под Xvfb (`oddyness form`)

`oddyness form <конфиг> <база> <справочник>` открывает окно формы; сохранённая запись попадает в базу (сессия базы
занята на время работы окна), при успехе печатается `id N`, закрытие без сохранения — код 1. Backend выбирает
goWidgets, `goWidgets_BACKEND=gtk` задаёт его жёстко. Подключены все backend goWidgets (cocoa, gtk, qt, win32,
headless); кросс-сборка без CGO для Linux, Windows и macOS — шаг `ci`.

Тест `TestNativeForm` (`cmd/oddyness/native_test.go`, включается `ODDYNESS_NATIVE_UI=1`; в CI с этой переменной
отсутствие Xvfb, xdotool или GTK — ошибка, а не пропуск) запускает отдельные процессы приложения: каждый сценарий
получает свой дисплей Xvfb (`:91`, `:92`), свою базу и свой процесс, ввод — настоящие нажатия клавиш xdotool
(XTEST) в настоящем окне GTK: Tab, текст, пробел на флажке, Return на «Сохранить». Сценарии идут параллельно:
1. «заполнить и сохранить»: все поля, флажок, число `10.500`; после выхода процесса запись читается из базы
   независимым `sqlite.Open` и совпадает.
2. «неверно, затем исправить»: Return на «Сохранить» пустой формы оставляет окно открытым (ошибки видны на снимке),
   затем ввод и сохранение; в базе ровно одна запись с ожидаемыми значениями.
Снимки экрана каждого сценария — артефакт `native-shots` прогона `ci`.

Этот сценарий нашёл ошибку окна: отражение каждого ввода возвращало фокус на контрол, который форма считала
сфокусированным, поэтому Tab не работал. Теперь фокус переводится только по команде формы (после неверного
«Сохранить»), а не при отражении ввода.

Проверено только на GTK (Linux, Xvfb без оконного менеджера, ввод ASCII). Не проверено: Qt, Win32, Cocoa, ввод
кириллицы, мышь, окно с оконным менеджером, DPI.

## Каталог: список и карточка (P06)

`forms.Catalog` — состояние окна каталога: список записей (`Rows`, `Columns`: номер и поля) и карточка (`Form`), которая
после успешного сохранения остаётся открытой (`KeepOpen`). Команды: `Select(i)` загружает запись в карточку (`Form.Load`),
`New()` очищает карточку (`Form.Reset`), `Card().Save()` добавляет запись или обновляет выбранную через `Backend`
(`List`, `Insert`, `Update`), затем перечитывает список и оставляет сохранённую запись выбранной — следующая правка
обновляет её, а не создаёт дубль. Проверки полей — прежние (пустое имя — `required`); дубликат кода и прочее решает ядро,
его ошибка остаётся в `FormError`, список и данные не меняются, ввод сохранён.

Окно — `ui.OpenCatalog`: `goWidgets.Table` со списком, кнопка «Новый» и карточка. Выбор строки пользователем загружает
запись в карточку; значения виджетов в этот момент выставляет программа, поэтому ввод не пересылается форме обратно
(`syncing`). Команда `oddyness app <конфиг> <база> <справочник>` открывает окно, запись идёт через `sqlite.Store`.

Проверка: `internal/forms/catalog_test.go` (создание, правка, выбор, дубликат, пустое имя, ошибка списка), окно на
headless-backend — `internal/ui/catalogcheck` (отдельный пакет: у headless-таблицы глобальное состояние), нативный
GTK под Xvfb — `TestNativeApp` (товар с занятым кодом оставляет окно открытым с ошибкой ядра, исправление и сохранение,
закрытие кнопкой, независимое чтение базы). Не проверено: выбор строки мышью и клавишами в нативном окне, Qt, Win32, Cocoa.

## Документы: список, шапка, строки (P16)

`forms.Documents` — состояние окна документов одного вида: список документов (`Rows`, `Columns`: номер, поля шапки и
«Проведён»), форма шапки (`Header`, контролы `<вид>/f/<поле>`), строки выбранного документа в памяти (`Lines`) и карточка
строки (`Line`, контролы `<часть>/f/<поле>`). Формы шапки и строки — `forms.NewFields`: поля без кнопок, команды вызывает
владелец. Поддерживается вид документа не более чем с одной табличной частью; больше — явная ошибка `NewDocuments`
(а не молчаливая потеря частей).

Команды: `New`, `Select(i)` (шапка и строки документа загружаются из ядра), `SelectLine`, `NewLine`, `SaveLine`
(проверка карточки строки; верная строка добавляется или заменяет выбранную, неверная остаётся в карточке с ошибками
полей — `ErrInvalid`), `DeleteLine`, `Save`, `Post`, `Unpost`. Строки живут в памяти до `Save`: документ записывается
целиком (шапка и все строки одной операцией ядра), новый добавляется, выбранный обновляется. `Post` — как «Провести» в 1С:
сначала записывает документ, затем проводит; проведённый документ проводится повторно без записи (S05). Документ,
чьё проведение отказано (недостаточный остаток, `Отказ` обработчика), остаётся записанным, но не проведённым; причина —
в `Error` (строка ошибки шапки). После `Post`/`Unpost` список и документ перечитываются из ядра, поэтому статус и
строки в окне — из базы, а не из памяти формы.

Все прикладные правила остаются за ядром: положительное количество, обязательный товар-ссылка, точность чисел,
уникальность номера, запрет правки проведённого документа (`sqlite.ErrPosted`), остаток, отмена, откат — форма только
показывает их ошибку. Формы проверяют лишь разбор ввода (обязательность, число, ссылка, точность), как и форма справочника.
Подключение к ядру — `formsbackend.Documents` (хранилище для записи, платформа для проведения и отмены).

Окно — `ui.OpenDocuments`: сверху две таблицы goWidgets (документы и строки выбранного), ниже поля шапки, поля карточки
строки и кнопки «Записать строку», «Новая строка», «Удалить строку», «Сохранить», «Провести», «Отменить проведение»,
«Новый документ», «Закрыть». Порядок обхода Tab — поля шапки, поля строки, кнопки (таблицы в обход не входят, так
нативный сценарий не зависит от их фокуса). Построение виджетов формы вынесено из `ui.open` в `panel` (`internal/ui/panel.go`):
окно справочника содержит одну панель, окно документов — две. Выбор строки таблицы пользователем загружает документ или
строку; значения виджетов в этот момент выставляет программа (`syncing`). Команда
`oddyness documents <конфиг> <база> <вид>` открывает окно вида (поступление — `receipt`, выдача — `issue`); сессия базы
занята на время работы окна.

Проверка: `internal/forms/documents_test.go` (настоящее ядро: S02, S03, S04, S05, S06, S07, S09, S10, S12 через команды
форм, состояние читается из базы независимо), окно на headless-backend — `internal/ui/documentscheck` (отдельный пакет:
у headless-таблицы глобальное состояние; выбор строки имитируется событием `Table.Selected`, потому что `PickTableRow`
берёт произвольную из нескольких таблиц), нативный GTK под Xvfb — `TestNativeDocuments/receipt` (поступление: пустой товар
оставляет окно открытым с ошибкой, строка, «Сохранить», «Провести», «Закрыть»; независимое чтение базы: документ проведён,
остаток 10.500), `TestNativeDocuments/issue` (выдача; сценарии поступления и выдачи идут параллельно, у каждого свой процесс, дисплей и база: две строки одного товара 5.000 + 4.000
при остатке 8.250 — «Провести» отказано целиком, окно открыто, документ записан, но не проведён (S10); новый документ на 2.250
проведён (S03); правка получателя проведённого документа и «Сохранить» — отказ ядра, документ прежний (S12); база читается
независимо, остаток 6.000). Не проверено: выбор строки мышью и клавишами в нативном окне (сценарии идут только через Tab и
кнопки, таблицы в обход не входят), ввод кириллицы, Qt, Win32, Cocoa.

## Граница

Данные в памяти или в переданной `SaveFunc`; подключение к базе — P06. Нативные backend, кроме GTK, не проверены (см. выше).

## Известное ограничение: высота таблиц

goWidgets этой ревизии не позволяет задать высоту `Table`, и в окнах с несколькими виджетами таблицы сжаты (видно на
снимках нативных сценариев). Тикет с воспроизведением и критерием: https://github.com/unxed/goWidgets/issues/43.
