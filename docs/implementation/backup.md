# Резервная копия и восстановление (P20)

Реализация — `internal/storage/sqlite/backup.go`, команды `oddyness db backup` и `oddyness db restore`.

- `Store.Backup(ctx, path)` — консистентная копия открытой базы через `VACUUM INTO` (согласованный снимок средствами
  SQLite; файл открытой базы никто не копирует вслепую). Файл `path` не должен существовать (`ErrExists`), недописанная копия при
  ошибке удаляется. Это чтение: доступно и роли чтения.
- `sqlite.Restore(ctx, backup, newPath, model)` — новая база из копии. До любой записи копия открывается обычным `Open`
  (версия схемы — `ErrVersion`, отпечаток конфигурации — `ErrConfig`, не база oddyness — ошибка) и проверяется `PRAGMA
  integrity_check` (`ErrCorrupt`). Существующая база `newPath` не перезаписывается (`ErrExists`), файл копии не меняется,
  недописанная база при ошибке удаляется; готовая база открывается как рабочая той же конфигурации.
- CLI: `oddyness db backup <конфигурация> <база> <копия>`, `oddyness db restore <конфигурация> <копия> <новая-база>`. Базу
  `backup` открывает как обычную сессию (занятую другим процессом — отказ, роль `ODDYNESS_ROLE=read` допустима).

Границы: автоматических миграций нет (копия другой конфигурации или версии отклоняется), восстановления произвольной базы
1С нет, копия не шифруется и не сжимается.

Проверка: `internal/storage/sqlite/backup_test.go` (S03 из копии после закрытия исходной базы: 8,250, документы проведены,
восстановленная база рабочая; отказы: существующая база и копия не меняются, мусор и усечённая копия, другая конфигурация,
другая версия схемы, путь с недопустимым символом — файлов не остаётся), `cmd/oddyness/backup_test.go` (то же через процесс,
копия под ролью чтения, usage).
