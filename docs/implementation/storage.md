# Хранилище справочников: SQLite без CGO (P05)

Реализация — `internal/storage/sqlite`, драйвер `modernc.org/sqlite` v1.61.0 (SQLite, перенесённый на Go).
Документация драйвера сверена по Context7 (DSN, `_pragma`, коды ошибок); места, в которых я не уверен без
запуска, перечислены ниже.

## Что делает

- `Create(путь, модель)` создаёт новую базу из метаданных (`config-format.md`): таблица `cat_<id>` на
  справочник, столбец `f_<id>` на поле, внешние ключи для `ref`, уникальные индексы для `unique`.
  Существующий файл не перезаписывается (`ErrExists`), недосозданная база удаляется.
- `Open(путь, модель)` открывает существующую. До любого изменения проверяются версия схемы
  (`PRAGMA user_version`, сейчас 1 — иначе `ErrVersion`) и отпечаток конфигурации (SHA-256 канонической
  записи модели в таблице `oddyness_meta` — иначе `ErrConfig`). Это отказ, а не миграция: смена
  конфигурации — P21.
- CRUD по идентификатору поля метаданных: `Insert`, `Get`, `Update`, `Delete`, `List`; запись одной
  транзакцией. Значения: `string`, `bool`, `value.Number`, `Ref{Catalog, ID}` (или `nil`).
- Ошибки: `ErrNotFound`, `ErrDuplicate` (уникальное поле), `ErrInvalid` (неизвестное или пропущенное
  поле, неверный тип, число вне `digits`/`scale`, ссылка на другой справочник или несуществующую запись,
  удаление используемой записи), `ErrUnknown` (справочник), `ErrLocked`.
- Числа хранятся точной десятичной записью (`TEXT`), `REAL` и `float64` не участвуют; значение с лишними
  знаками после точки или целыми цифрами сверх `digits - scale` **отклоняется, а не округляется**.
  Масштаб, с которым число записано, сохраняется.
- Одна локальная сессия: соединение единственное, `locking_mode=EXCLUSIVE`, при открытии берётся
  `BEGIN EXCLUSIVE`. Вторая сессия (в том же или другом процессе) получает `ErrLocked`, а блокировка
  снимается `Close` или завершением процесса (ОС снимает блокировки файла).

## Документы (P10)

`InsertDocument(вид, шапка, строки)` атомарно записывает шапку и строки всех табличных частей одной транзакцией;
`UpdateDocument` заменяет шапку и все строки черновика; `GetDocument`, `ListDocuments`, `DeleteDocument`
(строки удаляются каскадом). Строки хранятся с номером с единицы в порядке записи (`Record.ID` строки).
Всё проверяется до транзакции: поля шапки и строк, дата, `positive`, `required`, точность чисел; ошибки базы
(уникальность номера внутри вида, ссылка на несуществующую запись) откатывают шапку и все строки. Товар, на который
ссылается строка документа, удалить нельзя (`ErrInvalid`); после удаления документа — можно. Документ — только
черновик: он ничего не меняет в остатках (регистры — P11). Платформа не знает имён складских объектов: всё берётся
из метаданных. CLI: `oddyness document add|get|list` (`add … [поле=значение...] [--row часть поле=значение...]...`).

## Регистр накопления и остатки (P11)

Низкоуровневый API ядра — им пользуется проведение (P12), интерфейс его не вызывает.
- `Tx.ReplaceMovements(регистр, вид документа, номер, строки)` (и `Store.ReplaceMovements` в собственной транзакции)
  заменяет весь набор движений регистратора: прежние удаляются, новые пишутся со строками с единицы. Ключи строки —
  ровно измерения и ресурсы, значения проверяются по метаданным до записи; регистратор обязан существовать;
  ошибка базы (товара нет) откатывает и удаление прежнего набора. Повторная замена тем же набором остатки не удваивает.
- `Store.Tx(ctx, func(*Tx) error)` — одна транзакция на несколько операций (замены, чтения `Tx.Movements` и
  `Tx.Balances`, которые видят ещё не зафиксированное); ошибка функции откатывает всё. Через неё проведение
  в P12 запишет статус и движения вместе.
- `Balances(регистр, BalanceQuery{Filter, OrderBy, Desc, Nonzero})` — остаток на текущий момент: движения суммируются
  по сочетаниям значений измерений. `DeleteDocument` убирает и движения удаляемого регистратора.

**Решение о суммах и сортировке чисел.** Числа хранятся текстом (точной десятичной записью), поэтому SQL-агрегаты
(`SUM`) и `ORDER BY` по ним дали бы приблизительный или текстовый результат (`"10.5" < "9.99"`). Суммирование и
упорядочивание по числам выполняются **в ядре** точным `value.Number` (`Add`, `Cmp`) по записям движения;
порядок по умолчанию — по значениям измерений (пустая ссылка первой, ссылки по номеру, строки по байтам).
Кодирование, сохраняющее порядок, не вводилось: оно не нужно, пока остатки считаются по всем движениям регистра, а
доказуемую точность проще получить сложением `Number`. Цена — чтение всех движений выбранного регистра (измерение
производительности и итоги — P24). Сумма, не помещающаяся в 32 цифры, — явная ошибка, а не округление.

## Командная строка

```
oddyness db create <каталог-конфигурации> <файл-базы>
oddyness catalog add <каталог-конфигурации> <файл-базы> <справочник> <поле>=<значение>...
oddyness catalog get <каталог-конфигурации> <файл-базы> <справочник> <id>
oddyness catalog list <каталог-конфигурации> <файл-базы> <справочник>
```

Справочник и поле задаются именем (без учёта регистра) или `id`. Значения: строка как есть, булево
`true`/`false`, число — точным литералом, ссылка — числом `id` записи (пусто — пустая ссылка). Каждая
команда — отдельная сессия: база открывается и закрывается. Пример: `oddyness db create
testdata/configs/small-stock /tmp/s.db`, затем `oddyness catalog add testdata/configs/small-stock /tmp/s.db
Товары Код=K-1 Наименование=Кабель ЕдиницаИзмерения=м Используется=true МинимальныйОстаток=10.500`; другой процесс
выводит запись командой `catalog list`. Тест `TestCrossProcess` запускает отдельные процессы: один создаёт
товар, другой его читает; пока третий держит сессию, команды получают отказ «locked by another session», после
его завершения работают.

## Ограничения

- Сортировка и `SUM` по числовым полям на уровне SQL не поддержаны: текстовая запись числа не упорядочивается
  по значению. Решение (кодирование для упорядочивания или суммирование в ядре) принимается в P11/P17.
- `unique` только для строк; сравнение строк точное, по байтам UTF-8.
- Все поля обязательны, кроме `ref` (пустая ссылка — `NULL`). Значений по умолчанию нет.
- Блокировка основана на файловых блокировках SQLite: сетевые и необычные файловые системы не проверялись.
  Не проверено: поведение на Windows и macOS (кросс-сборка без CGO есть в CI, запуск тестов, в том числе межпроцессного, — только Linux).
- Не уверен без отдельной проверки: поиск «занято» опирается на текст ошибки драйвера
  («database is locked»/`SQLITE_BUSY`), а не на числовой код.

## Зависимости и лицензии

Связанные с пакетом модули (`go list -deps`, прогон `ci` 40581946317, Linux): `modernc.org/sqlite` (BSD-3-Clause,
сам SQLite — общественное достояние), `modernc.org/libc`, `modernc.org/mathutil`, `modernc.org/memory`
(BSD-3-Clause), `golang.org/x/sys`, `github.com/remyoudompheng/bigfft`, `github.com/google/uuid`
(BSD-3-Clause), `github.com/dustin/go-humanize` (MIT). На других платформах драйвер дополнительно может
связывать `github.com/mattn/go-isatty` и `github.com/ncruces/go-strftime` (MIT). Тексты лицензий проверены
по исходным модулям; `github.com/google/pprof` (Apache-2.0) есть в графе модулей, но не связывается.
`CGO_ENABLED=0`-сборка пакета для Linux, Windows и macOS — шаг `ci`.
