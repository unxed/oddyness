# Формат конфигурации oddyness (P02)

Каталог с файлом `metadata.json` (UTF-8, без BOM). Это собственный формат платформы, не XML/EDT/cf
1С и не их подмножество; загрузчик — `internal/metadata`, проверка — `oddyness config check <каталог>`.
Пример — `testdata/configs/small-stock` (авторский, BSD-3-Clause, часть сквозной конфигурации «Малый склад»).

```json
{
  "version": 1,
  "catalogs": [
    {"id": "goods", "name": "Товары", "fields": [
      {"id": "goods-code", "name": "Код", "type": "string"},
      {"id": "goods-min", "name": "МинимальныйОстаток", "type": "number", "digits": 15, "scale": 3},
      {"id": "goods-analog", "name": "Аналог", "type": "ref", "target": "goods"}
    ]}
  ]
}
```

- `version` обязателен, поддерживается только `1`; файл другой версии получает «unsupported version», а не
  ошибку про неизвестное поле.
- Идентификаторы (`id`) стабильны, не зависят от отображаемых имён, уникальны во всём файле (справочники и
  поля): латинские буквы, цифры, `_` и `-`, начало с буквы, до 64 символов. Имена уникальны (без учёта
  регистра) среди справочников и среди полей одного справочника.
- Типы поля: `string`, `boolean`, `number` (обязательны `digits` 1..32 и `scale` 0..`digits`; точная
  арифметика — `numbers.md`), `ref` (обязателен `target` — `id` справочника). `digits`/`scale` допустимы
  только у `number`, `target` — только у `ref`; `unique: true` (только у `string`) запрещает повтор значения
  поля в справочнике (уникальный код товара).
- Неизвестные поля, неизвестный тип, повтор `id`, битая ссылка, битый JSON и данные после объекта
  отклоняются. Ошибка называет файл, путь (`catalogs[0].fields[1].type`) и, где позицию можно указать
  точно (синтаксис JSON, неизвестное поле, неподдерживаемая версия), строку и колонку; семантические
  ошибки позиции не имеют, только путь.
- Загрузка атомарна: `metadata.Load` возвращает модель целиком или ошибку; `metadata.Store` при
  неудачной загрузке оставляет прежнюю действующую модель.

## Документы (P10)

Необязательный массив `documents`: вид документа — `id`, `name`, поля шапки `fields` (хотя бы одно) и табличные
части `tables` (`id`, `name`, `fields`; хотя бы одно поле). Идентификаторы документов, табличных частей и полей
входят в то же пространство, что и справочники; имена уникальны среди документов, среди табличных частей документа и
среди полей. Номер документа — строковое поле с `unique: true`: уникальность проверяется внутри вида документа.

Дополнения к полям (действуют и в справочниках): тип `date` (строка `ГГГГ-ММ-ДД`, календарно допустимая),
`positive: true` у `number` (значение больше нуля — количество), `required: true` у `ref` (обязательная ссылка;
остальные типы обязательны всегда). Пример — `receipt` и `issue` в `testdata/configs/small-stock`.

Не поддержано сейчас: регистры, формы, файлы BSL, миграции версий, импорт XML/EDT/cf.
Сверка с оригиналом неприменима: формат собственный.
