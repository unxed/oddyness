# Изменение конфигурации: безопасный отказ (P21)

Реализация — `internal/storage/sqlite/schema.go`, `checkConfig` в `store.go`.

База привязана не ко всей конфигурации, а к её **схеме**: при создании в таблицу метаданных записываются отпечаток схемы и её
каноническое описание (строки `catalog|document|table|register … field <id> type digits scale target unique`, отсортированные).
`Open` сверяет с ней текущую конфигурацию.

- **Допустимо без миграции** (схема не меняется): подписи (`name`) объектов и полей, признаки проверки ввода (`required`,
  `positive`), обработчики проведения и отмены, отчёты. База открывается новой конфигурацией, данные на месте.
- **Отклоняется при открытии, до любой записи** (`ErrConfig`): другой тип поля, удалённое или новое поле, другой `id`,
  точность (`digits`, `scale`), цель ссылки, уникальность, новый или удалённый объект (справочник, документ, табличная часть,
  регистр). Сообщение перечисляет различия (`- было в базе`, `+ стало в конфигурации`) и называет причину: нужна миграция,
  а миграций пока нет. Прежняя конфигурация по-прежнему открывает базу.
- База, созданная до сохранения схемы (в ней только отпечаток всей модели), открывается лишь неизменённой конфигурацией.

`Restore` (P20) использует ту же проверку: копия, снятая по другой структуре, отклоняется.

Граница: визуального конфигуратора и универсального мигратора нет; добавление поля или объекта тоже требует будущей миграции
(таблицы и столбцы не создаются на лету).

Проверка: `internal/storage/sqlite/schema_test.go` (изменение подписей и признаков допустимо, данные целы; девять видов
структурных изменений отклоняются с перечнем; прежняя конфигурация открывает базу; база без схемы), `cmd/oddyness/schema_test.go`
(то же через процесс: переименование подписи работает, смена типа — отказ с сообщением о миграции, запись отклонена, данные прежние).
