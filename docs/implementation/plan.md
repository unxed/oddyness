# План реализации для последовательной работы бота

Состояние на 2026-10-21: **все P01–P25 запланированы, код не реализован**.
Предыдущий патч содержал исследование; этот фиксирует согласованную архитектуру
и порядок её проверки. Зависимости перечислены явно; номера задают предпочтительный
порядок, но независимую готовую карточку можно делать, пока другая заблокирована.

Перед началом: [архитектура](architecture.md), [процесс RUP](workflow.md),
[прикладной сценарий](test-configuration.md). Карточка — верхняя граница итерации:
если она велика, разбить на меньшие проверяемые части. Для каждой части обязательны
тесты вместе с кодом и видимый результат. Не выполнять весь файл одним поручением.

В строку `Статус` завершённой карточки добавить commit/PR и команду/артефакт
проверки. Пока таких свидетельств нет, `planned` остаётся честным статусом.
Пути и имена команд ниже — будущие точки входа, их отсутствие сейчас ожидаемо.

## После первого preview, отдельными решениями

Полный конфигуратор, импорт XML/EDT/cf, PostgreSQL/сервер, несколько пользователей,
аутентификация, расширенная BSL/SDBL, управляемые формы, DCS/печать, дополнительные
регистры и Wasm-компоненты требуют собственных риск-ориентированных итераций.
Не включать их незаметно в текущие карточки. Практическую конфигурацию развивать
отдельно; новые нужды конфигурации должны порождать общие механизмы платформы,
а не специальные ветви по именам её объектов.
