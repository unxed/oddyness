# Нативные платформы: что проверено реально (P23)

Кросс-компиляция не равна запуску. Здесь перечислено только то, что выполнялось на ОС в CI; всё остальное — ограничение.
goWidgets закреплён на ревизии `5f71d2bacbd1` (23-10-2026); сборки без CGO (`CGO_ENABLED=0`).

| ОС и backend | Что выполняется | Где | Ввод |
| --- | --- | --- | --- |
| Linux, GTK 3 под Xvfb (без оконного менеджера) | все тесты; `TestNativeForm` (2 сценария), `TestNativeApp`, `TestNativeDocuments/receipt`, `/issue`, `/report` — отдельные процессы, свой дисплей и база, независимые сценарии параллельно; upstream-тест таблицы goWidgets на GTK | workflow `ci`, ubuntu-latest | настоящие нажатия xdotool (XTEST) |
| Windows, Win32 | `go vet`, `go test -p 1 ./...` (все пакеты, включая SQLite без CGO); сценарий окна поступлений `tools/native/windows-documents.ps1`: шапка, строка без товара (ошибка поля, окно открыто), строка, сохранить, провести, закрыть, затем чтение базы консольным `oddyness` (документ проведён, остаток 10.500) | workflow `native-os`, windows-latest | настоящие нажатия `SendKeys`; кнопка — пробел |
| macOS, Cocoa | `go vet`, `go test -p 1 ./...`; окно поступлений запущено, у процесса есть видимое окно (`CGWindowList`), снимок экрана — артефакт | workflow `native-os`, macos-latest | ввода нет: у раннера нет прав Accessibility |

Команды: `go test ./...` (все ОС); Linux — `ODDYNESS_NATIVE_UI=1 go test -count=1 -v -run 'TestNativeForm|TestNativeApp|TestNativeDocuments' ./cmd/oddyness`;
Windows — `./tools/native/windows-documents.ps1` после сборки `oddyness.exe` и `oddyness-gui.exe`; macOS — `bash tools/native/macos-documents.sh`.
Снимки экрана и логи — артефакты прогонов (`native-shots`, `native-os-windows`, `native-os-macos`).

## Сценарии S01–S12 по платформам

- Linux GTK, окно и клавиши: S01 (товар, ошибка дубликата и исправление), S02 (поступление, проведение), S03, S04/S10 (отказ выдачи
  целиком), S09 (пустой товар), S12 (правка проведённого — отказ), отчёт «Остатки» (читается по трассе команд). Остальное (S05–S08,
  S11 в окне) проверяется на Linux headless-backend и ядром (`internal/ui/*check`, `internal/platform`, `cmd/oddyness`).
- Windows Win32: часть S02 и S09 в окне; S01, S03–S08, S10–S12 в окне Windows не выполнялись (ядро и формы на Windows проверены
  тестами без окна).
- macOS Cocoa: окно открывается; сценариев ввода нет.

## Ограничения (непроверенное остаётся ограничением)

- Qt backend не запускался; ввод кириллицы в нативных окнах не проверялся; мышь, оконные менеджеры, DPI, фокус при сворачивании не проверялись.
- На Windows и macOS не выполнялись сценарии выдачи, отмены, отчёта и роли чтения в окне; macOS не проверяет ввод и закрытие.
- Окно 760×1100 не умещается в экран раннера (Windows 1024×768, macOS ограничивает высоту): кнопки внизу не видны, но доступны с клавиатуры;
  высота таблиц goWidgets не настраивается (https://github.com/unxed/goWidgets/issues/43). «Довести требуемые контролы backend upstream»:
  обязательной доработки goWidgets для поддержанных сценариев не потребовалось, кроме перечисленного тикета.
- Подпись «Test Mode» и чужие окна на снимках Windows — стенд раннера. Прогон Windows и macOS не входит в обязательные проверки PR.

Находки этой карточки на Windows: перенос строк CRLF при выгрузке (добавлен `.gitattributes`), текст ошибки отсутствующего файла другой,
в тесте сессии не закрывалась база (на Windows нельзя удалить открытый файл), бюджеты времени проведения (fsync) действуют только на Linux, а
Enter не нажимает фокусную кнопку Win32 (нажимается пробелом).
