# Роли чтения и оператора (P19)

Реализация — `internal/storage/sqlite/role.go`. Роль — локальное правило ядра для приложения, которое открыло базу;
это **не аутентификация** и не защита от владельца файла SQLite (он может открыть базу чем угодно). Сеть, пользователи и
права на отдельные объекты вне границ первой поставки.

## Роли

- `RoleOperator` (`operator`) — чтение и запись; роль по умолчанию, поэтому прежние вызовы `Open` не меняются.
- `RoleReader` (`read`) — только чтение: каталоги, документы, движения и остатки читаются (`Get`, `List`, `GetDocument`,
  `ListDocuments`, `Movements`, `Balances`; запросы и отчёты идут через них), любая запись отклоняется `ErrDenied`.

`Store.SetRole`, `Store.Role`, `Store.CanWrite`, `sqlite.ParseRole` («read»/«reader»/«operator» без учёта регистра).

## Где проверяется

Каждая публичная операция записи проверяет роль первой строкой, до проверки значений: `Insert`, `Update`, `Delete`,
`InsertDocument`, `UpdateDocument`, `DeleteDocument`, `Tx` (а значит и `ReplaceMovements`). Страховка — `inTx`: все записи
идут через неё, поэтому новая операция записи не обойдёт роль, даже если забудет явную проверку. Платформа проверяет роль в
`Post` и `Unpost` до выполнения обработчика: под ролью чтения BSL не запускается и не может вызвать `Движение`; отказ несёт
`ErrDenied` с названием операции и роли. Отказ ничего не оставляет записанным (операция не начиналась).

Окно (P19, часть 2) только показывает недоступные команды (`CanWrite`); защитой служат проверки ядра.

## CLI

`ODDYNESS_ROLE=read oddyness …` открывает базу в режиме чтения (`document post`, `catalog add` и т. п. — отказ с кодом 1,
`catalog list`, `register balance`, `query` — работают); неизвестное значение — ошибка до открытия базы; пусто или
`operator` — запись разрешена. Роль применяют все команды, открывающие базу (`openSession`).
