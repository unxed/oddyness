# Отчёты по остаткам (P18)

Отчёт описывается в метаданных (`reports`): `id`, `name` и `query` — текст запроса на языке `docs/implementation/query.md`.
Параметры отчёта — параметры запроса `&Имя`; форма отчёта строится из них. Пример (`testdata/configs/small-stock`):

```
ВЫБРАТЬ Товар, Количество КАК Остаток
ИЗ РегистрНакопления.Запасы.Остатки
ГДЕ Товар = &Товар
УПОРЯДОЧИТЬ ПО Товар
```

## Необязательные параметры

Параметр отчёта необязателен: пустая ссылка (или отсутствие значения) означает «не отбирать по этому параметру», поэтому
пустой «Товар» показывает остатки по всем товарам. Реализует это `query.WithoutParams`: она вырезает из отбора условия,
использующие незаданные параметры, но только целые верхние конъюнкции (`А = &П И Б > 0`: вырезается `А = &П`). Параметр под
`ИЛИ` или `НЕ` — явная ошибка при формировании, а не догадка о смысле «не задано». Пустая ссылка как настоящее значение
фильтра («только строки без товара») этим не выразима. Отчёт, чей запрос не разбирается или имеет параметр не ссылочного типа,
не открывается: форма отчёта умеет только фильтр по справочнику (`oddyness config check` разбирает все отчёты и сообщает ошибку
с позицией).

## Состав

- `metadata.Report`, раздел `reports` (строгая загрузка: неизвестное поле, повтор id и имени, пустой запрос — ошибки с путём);
  отчёт входит в отпечаток конфигурации, как и всё остальное в метаданных.
- `internal/report` — `Load` (по id или имени; запрос разбирается по метаданным), `Run` (значения параметров `value.Ref` или `nil`).
- `forms.Report` — состояние окна без виджетов: форма параметров (`NewFields`, контролы `<отчёт>/f/<параметр>`, все необязательны),
  `Run`, результат (`Columns`, `Rows` в тексте) и `Error`. Неверный параметр — `ErrInvalid`, прежний результат остаётся;
  ошибка ядра очищает результат. Правка параметров результат не меняет — он обновляется только командой.
- `formsbackend.OpenReport` — связь с хранилищем: запрос идёт через ядро (`Store.Balances`), сравнения и суммы — точным `Number`.

Тесты: `internal/query/optional_test.go` (вырезание условий, пересчёт параметров, отказы), `internal/report/report_test.go`
(настоящее ядро: пустой склад, несколько товаров, дробные количества, фильтр, обновление после проведения и отмены,
S03), `internal/forms/report_test.go` (форма отчёта).


## Окно и команда

`ui.OpenReport` — окно отчёта: таблица результата (`goWidgets.Table`, заголовки известны по описанию отчёта до первого
запуска), поля параметров и кнопки «Сформировать» и «Закрыть». Результат обновляется только командой «Сформировать»
(после проведения или отмены документа нужно сформировать отчёт заново); неверный параметр показывает ошибку поля, прежний
результат остаётся. Порядок Tab: поля параметров, «Сформировать», «Закрыть» (таблица выше и в обход не входит); после команды
фокус возвращается на первый параметр. Таблица обновляется только при изменении содержимого (`syncTable`, как в окне
документов: лишний `SetRows` порождает сообщения о выборе в нативных backend).

Команда `oddyness report <конфиг> <база> <отчёт>` (id или имя отчёта) открывает окно; сессия базы занята на время работы.
`ODDYNESS_UI_TRACE=1` печатает в stderr результат каждой команды окна (нативный сценарий читает по нему таблицу, которую
нельзя прочитать из окна ОС).

Проверка окна: `internal/ui/reportcheck` (headless-backend, настоящее ядро: пустой склад, несколько товаров, дробные
количества, фильтр, неверный параметр, обновление после проведения и отмены, S03), нативный GTK под Xvfb —
`TestNativeDocuments/report` (команда `oddyness report`: без параметра два товара 8.250 и 0.125, товар 2, неверный параметр,
очистка; результат читается по трассе). Не проверено: выбор строки таблицы, Qt, Win32, Cocoa.
