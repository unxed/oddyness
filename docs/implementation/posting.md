# Проведение документа: событие, BSL и одна транзакция (P12)

Реализация — `internal/platform` (прикладное ядро), `internal/vm` (функции хоста), `internal/storage/sqlite`
(`Store.Tx`, статус документа, движения), команда `oddyness document post`.

## Событие проведения в метаданных

У вида документа необязательное описание `"posting": {"file": "bsl/receipt-posting.bsl", "procedure": "ПриПроведении"}`:
относительный путь внутри каталога конфигурации (без `..`, абсолютных путей и пустых частей) и имя процедуры.
Файл не читают метаданные: `platform.Open` загружает, разбирает и компилирует каждый обработчик и не открывается с
неисправным (нет файла, ошибка разбора или компиляции с `файл:строка:колонка`, нет процедуры, число параметров не
равно одному). Пример — `receipt` в `testdata/configs/small-stock`. **Прикладной логики в Go нет**: что считать
движением поступления, написано в BSL (`bsl/receipt-posting.bsl`); платформа не знает слов «поступление», «товар».

## Что видит обработчик

- Параметр — документ: объект с полями шапки и табличными частями **по именам из метаданных**
  (`Документ.Номер`, `Документ.Дата`, `Для Каждого Строка Из Документ.Товары Цикл … Строка.Товар`).
  Табличная часть — таблица `vm.Table`, ссылка на справочник — значение `Ссылка` (BSL хранит, сравнивает на равенство
  и передаёт хосту; полей записи через неё не читает).
- Встроенная функция `Движение(Регистр, значения…)`: регистр — именем или `id`, дальше значения измерений и
  ресурсов **по порядку описания** в метаданных регистра. Функция только готовит движение: тип каждого значения
  сверяется с полем (строка/дата — Строка, число — Число, ссылка — Ссылка на нужный справочник), иначе ошибка
  «argument N (поле): expected …». Другого доступа к данным (SQL, файлы, запись) у BSL нет.

## Транзакция

`Platform.Post(ctx, вид, номер)` в одной `Store.Tx`: читает документ, выполняет обработчик, затем во **всех**
регистрах заменяет движения документа собранным набором (регистр без движений очищается) и ставит признак проведения.
Любая ошибка — BSL (деление на нуль, неверный тип, неизвестный регистр или колонка), лимит инструкций VM
(`Options.MaxSteps`), проверка или запись движения (в тесте — четыре знака вместо трёх на второй строке) — откатывает
всё: статус, прежние и новые движения не меняются. Повторное проведение заменяет набор тем же и остатки не удваивает.
`Document.Posted` показывает статус; `document get` печатает `[posted]`; `register balance` — точные остатки.

## Проверки

Через API (`internal/platform/post_test.go`): S02 (до проведения остатка нет, после — `10.500`, статус сохраняется
после перезапуска базы), S05 (повторное проведение не дублирует движения), S08 (ошибка после подготовки первого
движения: ноль частичных записей, повтор с исправленным обработчиком успешен), неверный тип движения, лимит VM,
ошибка записи на второй строке, ошибки загрузки обработчика с позицией; через CLI — проведение и остатки.

## Выдача и проверка остатка (P13)

Проведение выдачи — тот же механизм: `issue` в метаданных указывает `bsl/issue-posting.bsl`. Две новые функции хоста:
- `Остаток(Регистр, значения измерений по порядку)` — число: остаток единственного ресурса регистра в **той же транзакции**
  (`Tx.Balances`) плюс движения, уже подготовленные этим обработчиком по тем же измерениям. Поэтому несколько строк
  одного товара суммируются без коллекций в BSL: 5,000 + 4,000 при остатке 8,250 — вторая строка видит 3,250.
- `Отказ(Сообщение)` — прекращает проведение; `Post` возвращает `ErrRejected` с сообщением, транзакция откатывается целиком.

Перед запуском обработчика `Post` снимает собственные движения документа (в той же транзакции), поэтому при повторном
проведении выдачи её прежние движения не занижают доступный остаток, а итог не удваивается. Остаток считает ядро по
движениям: клиентскому предварительному расчёту доверия нет.

Ядро запрещает `UpdateDocument` и `DeleteDocument` для проведённого документа (`sqlite.ErrPosted`); черновик правится
и удаляется как раньше. Снять статус сможет отмена проведения (P14). Используемый товар по-прежнему удалить нельзя.

Проверки (`internal/platform/issue_test.go`): S03 (с перезапуском), S04, повторное проведение, S10, выдача товара без
остатка и пустая выдача, S12, ошибки аргументов `Остаток`/`Отказ`. S09 (ввод 0, отрицательного, лишних знаков, пустого
товара) обеспечивают проверки полей документа P10.

Не входит: отмена проведения (P14), права (P19). Остаток «на дату» и задние числа не поддерживаются.
